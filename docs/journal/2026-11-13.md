## Discoveries
- Le catalogue était déjà lu par `fetch_models` ; seul le choix était verrouillé, en trois endroits (garde Rust, constante envoyée par le front, sélecteur). Cache Codex de la machine (`~/.codex/models_cache.json`, lu le 13/11) : `gpt-6.1-sol`, `gpt-6-astra`, `gpt-6.1-terra`, `gpt-6-sol`, `gpt-6-luna`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` visibles. C'est le cache de Codex CLI, pas la réponse reçue par Doku. (journal seul : rediscoverable depuis le code)
- `npm run build:installer:arm64` lancé depuis Git Bash échoue à la préparation du sidecar (`tar: This does not look like a tar archive`) : GNU tar ne lit pas le zip d'Ollama. Relancé depuis PowerShell, il passe. Déjà écrit en commentaire dans `scripts/prepare-ollama-sidecar.mjs` (l. 109-111), que je n'avais pas lu. (non retenu : le dépôt le porte déjà)
- Le premier essai, passé par `| tail`, a rendu un code de sortie 0 alors que npm avait échoué ; c'est la date de l'installateur (5/11 au lieu du 13/11) qui a montré l'échec. (non retenu : déjà couvert par les leçons machine sur les marqueurs de complétion)
- `cargo fmt -- src/openai.rs` a reformaté le crate entier : `compat.rs`, `main.rs`, `sidecar.rs`, `sse.rs`, `web_search.rs` modifiés sans le vouloir. Prouvé format seul (`git show HEAD:… | rustfmt` identique au fichier), puis restaurés par `git checkout --` (ils étaient propres au début de la session). L'installateur de 12:26 a été compilé avec ce formatage, sans effet sur le comportement. Pour un seul fichier : `rustfmt <fichier>`. (non retenu : déjà dans le store machine, LES-20261002-014)
- L'effort de raisonnement reste `low` (ou `high` avec « Réfléchir ») pour tous les modèles ; `supported_reasoning_levels` du catalogue n'est pas lu.
- `OPENAI_MODELS_URL` porte `client_version=1.0.0` : hypothèse, non vérifiée, que le backend ne masque aucun modèle récent pour cette version.

## Decisions
- Garde côté Rust conservée : la webview ne peut demander qu'un modèle présent au catalogue du compte.
- Le modèle passe en paramètre à `src/lib/openai.ts` ; le module ne dépend pas du store.
- ADR-0013 et ADR-0014 décrivent encore Luna comme modèle unique : non amendés, décision laissée à l'utilisateur.
