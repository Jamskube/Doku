# Journal — 2026-08-12

## Summary
Doku dispose maintenant d'un installateur Windows x64 reproductible, testé localement et sur GitHub Actions. La régression de l'animation des points pendant le streaming a également été corrigée. Le bouton `+` du chat ajoute désormais un contexte éphémère borné, et la mémoire cloud durable est isolée par document par défaut avec partage de dossier uniquement sur choix explicite. Vérifications exécutées : `npm run check`, `npm test` (452 tests), `npm run build`, `npm run tauri build -- --bundles nsis`, `npm run build:installer:x64`, contrôle PE x64, smoke HTTP Ollama 0.32.0 et vérification visuelle navigateur en thèmes clair/sombre.

## Discoveries
- Le payload Ollama x64 CPU charge `llama-server.exe` et génère réellement avec Qwen sous Windows x64.
- L'installateur NSIS Tauri courant installe silencieusement dans `%LOCALAPPDATA%\Doku` ; le dossier `/D=` attendu n'était pas utilisé par le smoke test initial.
- Préparer le sidecar x64 remplace le contenu de staging `src-tauri/binaries/lib/ollama/` par son architecture ; relancer `npm run prepare:ollama:arm64` avant un prochain build ARM64, et inversement.
- Une mémoire inférée depuis l'explorateur ou le dossier parent transforme trop facilement `Desktop` en « projet » : la portée sûre est le document, le dossier restant un partage volontaire et visible.

## Decisions
- Le paquet x64 embarque uniquement le moteur Ollama CPU nécessaire afin de garder l'installateur à environ 20 Mo.
- Le build x64 est reproductible par commande locale et par workflow GitHub manuel ou déclenché sur tag `v*`.
- Les ajouts du bouton `+` restent éphémères, retirables et purgés avec une nouvelle conversation ; les chemins locaux ne sont jamais envoyés au fournisseur.
- La mémoire durable fonctionne uniquement avec OpenAI et MiniMax, reste locale en Markdown et s'attache par défaut à la note enregistrée ; un dossier n'est partagé qu'après un geste explicite.
