# 2026-09-09 — Images collées, Markdown portable, version 3.5.1

_Session menée par un autre agent ; reconstituée le 2026-09-11 depuis le diff et la conversation rapportée par le mainteneur._

## Summary

Un bug de collègue : une image collée dans une note **neuve** ne s'affiche qu'après redémarrage. Cause : le dossier de résolution des images était figé à la création de l'éditeur. Puis une demande produit : un `.md` envoyé seul perd ses images. Réponse : un export « Markdown portable » qui intègre les images locales en `data:` base64, avec les octets d'images exclus du contexte IA et du RAG. Version 3.5.1, deux installateurs. Aucun commit.

## Added

- `src/lib/export/portable-markdown.ts` (+ test) — copie `*-portable.md` avec images intégrées ; images manquantes signalées.
- `src/lib/editor/live-preview-dir.test.ts` — la facette de dossier se reconfigure.
- `src/lib/tauri.ts::saveMarkdownDialog`.
- `src/components/TitleBar.svelte` — entrée « Markdown portable » dans Exporter, pour les `.md`.

## Modified

- `src/lib/editor/live-preview.ts` — `docDirFacet` dans un `Compartment` ; `DocumentView.svelte` le reconfigure quand `tab.path` change.
- `src/lib/images.ts::omitEmbeddedImageData` — appliqué dans `copilot.svelte.ts` (question, résumé, documents automatiques, contexte), `rag.ts::chunkText`, et pour le seuil `heavy` (`stores.svelte.ts`, `DocumentView.svelte`).
- Version 3.5.1 partout.

## Decisions

- **Pendant l'édition, les images restent des fichiers voisins** ; la portabilité est un export explicite, pas le format de travail.
- **Un Markdown portable n'est pas « lourd »** au sens du seuil texte, pour rester en prévisualisation. *(plafond brut ajouté le 09-11)*
