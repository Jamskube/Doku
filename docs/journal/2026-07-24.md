## Discoveries (NPU — le cœur de la session)
- **Foundry Local 0.10.2 ne provisionne PAS l'EP QNN** sur cette Surface Pro 11 : `AutoRegisterCertifiedEps: Failure` (« Unknown EP bootstrapper name(s) »), `discoverEps()` ne voit que WebGPU. WinML QNN EP installés au niveau OS mais non câblés. Bug de maturité upstream, pas notre config.
- **La voie qui débloque** : `onnxruntime-qnn` (DLLs Qualcomm + skels Hexagon v73/v81) + `onnxruntime-genai` (`is_qnn_available`, `register_execution_provider_library`) ; `append_provider('QNNExecutionProvider')` + `backend_path`=QnnHtp + **`ADSP_LIBRARY_PATH`** vers les libs. Le `qwen2.5-1.5b-instruct-qnn-npu` (cache Foundry) charge sur le HTP en ~4 s.
- **Piège modèle** : `sliding_window.window_size=64` → `max_length` doit être ≥ 64 sinon `seqlens_k out of range`. Décodage glouton d'un 1.5B **boucle** (« prépré… ») → **repetition_penalty obligatoire**.
- **Mesures apples-to-apples** (même modèle) : NPU **prefill 4-6× plus rapide** que CPU (1.5b : 1,2 s vs 4,9 s @440 tok ; pente NPU ~1,5 ms/tok, plate) mais **decode ~2× plus lent** (22 vs 44 tok/s). Croisement L* favorable aux longs docs (prefill-dominé).
- **Le squeeze qualité/RAM (= le vrai mur)** : `1.5b-qnn` tient en RAM mais **trop bête** (quantif QNN agressive) ; `7b-qnn` (téléchargé `llmware/qwen2.5-7b-instruct-onnx-qnn`) **bon FR** mais **~5 Go → swap sur 16 Go** (a OOM une fois ; prefill 10,6 s, decode 7,8 t/s = ~4× plus lent bout-à-bout que le CPU 1.5b) ; **pas de 3B QNN** public pour le juste milieu. Machine 32 Go l'aurait fait voler.
