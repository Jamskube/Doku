## Discoveries
- **`reasoning_split` ne coupe rien.** Le paramètre a tout l'air d'un frein — il ne fait que router la pensée hors du contenu. Le modèle réfléchit autant ; on ne le voit simplement plus, ce qui rend l'attente **muette** au lieu de la raccourcir. Confirmé sur la doc MiniMax.
- **`thinking: {"type":"disabled"}` n'agit que sur M3** ; les M2.x l'ignorent, réflexion incluse. Le défaut de Doku est resté `MiniMax-M2.5` — un nouvel utilisateur atterrit donc sur le modèle que le correctif ne peut pas accélérer.
- **Les configs par plateforme de Tauri 2 suivent RFC 7396** : une clé à `null` est *supprimée*. C'est ce qui a permis de retirer le sidecar côté Linux sans toucher au fichier de base, donc sans remettre en jeu des installateurs qui marchent.
- **Un jeton OAuth sans portée `workflow` ne peut pas pousser un fichier de workflow** — le push est refusé sur ce seul fichier, tout le reste étant prêt. `gh auth refresh -s workflow` règle la cause ; pousser en SSH la contourne, ce qui aurait laissé le blocage revenir au commit suivant.
- **`keyring` 4 installe le magasin de la plateforme paresseusement au premier `Entry::new`** (feature `v1`, `LazyLock`), et sur \*nix c'est le Secret Service en `zbus` — du Rust pur. Vérifié **dans le code source de la caisse** : sans ça, on livrait du code qui compile et casse à l'exécution sur « aucun magasin par défaut ».
- **L'API des releases GitHub expose un `digest` sha256 par asset.** Épingler l'empreinte d'une archive de 1,44 Go ne demande pas de la télécharger — et les empreintes Windows déjà épinglées dans le script correspondent au bit près, ce qui valide la source.
- **`prepare-ollama-sidecar.mjs` exige le `tar.exe` de Windows** (bsdtar) : lancé depuis Git Bash, dont le GNU tar ne lit pas les zip, il échoue sur « Not found in archive ». Le piège est écrit dans le script — je suis tombé dedans quand même, parce que le `&&` derrière un pipe masquait le code de sortie.

## Decisions
- **v3.0.0.** L'application avait énormément bougé depuis 2.2.0 ; un installateur avait même été renommé `2.4.0` à la main.
- **La réflexion de MiniMax est coupée pour la conversation aussi**, pas seulement pour les appels internes — c'est ce qui rend M3 vif, et c'est aligné sur le bridage d'OpenAI à l'effort `low`. On y perd de la profondeur sur les questions difficiles ; c'est un `"disabled"` à passer en `"adaptive"` si l'arbitrage change.
- **`thinking` n'est envoyé qu'aux M3.** La doc dit que les M2.x l'ignorent, mais « ignoré d'après la doc » ne vaut pas « accepté par le service » : ne l'envoyer qu'aux modèles où il agit fait passer le risque de faible à nul.
- **Linux = AppImage + Ollama du système** (ADR-0025). Empaqueter 1,44 Go pour dupliquer ce qu'un `pacman -S ollama` fait mieux, et met à jour tout seul, n'a aucun sens. Le sidecar Windows n'existe que parce que Windows n'a pas de gestionnaire de paquets sur lequel compter.
- **Windows n'est PAS migré sur `keyring`** (ADR-0026). La convention de nommage des identifiants y diffère : basculer orphelinerait **en silence** les secrets déjà stockés — compte OpenAI déconnecté, clé MiniMax disparue, sans message ni cause visible. Une seconde implémentation coûte moins cher.
- **README en anglais, le reste de `docs/` en français.** Le dépôt est public et les visiteurs lisent l'anglais ; la documentation de travail reste écrite pour ceux qui construisent.
