**Critère de fin** : un `.docx` issu de la conversion s'ouvre, s'édite et se réexporte depuis l'application ; `npm run check` et `npm test` verts ; installateurs ARM64 et x64 construits sur `HEAD`.

## Décisions autonomes
| Décision | Défaut choisi | Pourquoi | Réversible |
|---|---|---|---|
| Modules de collaboration SuperDoc | Talon vide aliasé dans `vite.config.ts` | Imports à effet de bord seuls, aucune liaison utilisée ; Doku est mono-poste et hors ligne | Oui — retirer l'alias, installer les paquets |
| `yjs` | Installé | Réellement importé (`import { Map } from "yjs"`), local, sans réseau propre | Oui |
| Prédicat `isBinaryKind` | Garde de type, remplace les `kind === 'pdf'` épars | Un booléen laisserait `docx` filer jusqu'à l'écriture texte et écraser le fichier | Oui |
| Bouton « Exporter en PDF » du DOCX | Retiré | Mesuré cassé (ZIP vide) ; un bouton qui ment est pire que pas de bouton | Oui — le rebrancher quand une voie fiable existe |
