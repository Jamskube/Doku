## Situation
Gotchas — portée `securite`. Entrée d'origine datée du 2026-07-16.

## Rule
Rendre du contenu LLM (chat copilote) = ALLOWLIST DOMPurify, jamais un denylist.

## Evidence
Le chat rend la réponse du modèle (non fiable) dans la **webview PRINCIPALE**, pas l'iframe sandboxée de l'aperçu. La CSP `main` (tauri.conf.json) n'a **pas de `default-src`** → toute directive absente est non restreinte → la garantie « 0 réseau » (principe 8.3) repose sur **DOMPurify seul**. Un `FORBID_TAGS:['img']` laisse passer `<video>/<audio>/<source>/<track>/<svg><use href>/<image href>/<input type=image>` = autant de beacons ; et interdire le **tag** `<style>` ne retire pas l'**attribut** `style="background:url(http://…)"`. Seule défense robuste (et stable aux versions) : `DOMPurify.sanitize(html, { ALLOWED_TAGS: [<sortie de marked GFM only>], ALLOWED_ATTR: [minimal, PAS 'style'/'src'/'srcset'], ALLOW_UNKNOWN_PROTOCOLS:false })` sans `WHOLE_DOCUMENT` (fragment). Le hook module-level `afterSanitizeAttributes` (retire href des ancres non-`#`) s'applique à TOUTES les instances → liens LLM inertes. Défense en profondeur : durcir la CSP `main` (`media-src/base-uri/form-action 'none'` — éviter `frame-src`/`default-src`/`font-src` qui cassent l'aperçu iframe/IPC/polices). `sanitizeChatHtml` (src/lib/sanitize.ts) + test de non-régression réseau obligatoire (payload hostile → 0 URL http). Voir la primitive d'aperçu sandboxé `sanitizeHtml` (contexte inverse : iframe + CSP `default-src none`, donc `WHOLE_DOCUMENT` + `<style>` conservés)
