## Situation
Workarounds — portée `tauri`. Entrée d'origine datée du 2026-08-11.

## Rule
Vérif navigateur d'une UI dépendante d'état IA (messages, statuts, modèles) SANS natif : passer par le graphe de modules Vite.

## Evidence
En dev, `await import('/src/lib/copilot.svelte.ts')` depuis `browser_evaluate` renvoie la MÊME instance de module que l'app (Vite dédoublonne) → pousser directement dans les `$state` exportés (`copilot.messages.push(...)`, `copilot.models = [...]`, `app.copilotProvider = ...`) et exercer les VRAIS handlers Svelte aux vrais gestes. A permis de vérifier l'aperçu de citations (survol/focus/scroll) et le dropdown modèle avec modèles installés + embed, sans sidecar ni clé API. Limite : dev serveur uniquement (les modules buildés sont hashés/inlinés). **PIÈGE (vécu le 11-08) : dès qu'on a ÉDITÉ le module dans la session, l'app tourne sur la version invalidée par HMR (`…/copilot.svelte.ts?t=1786443555274`) — un `import` de l'URL nue rend une SECONDE instance (state muté, DOM inchangé, aucune erreur).** Un `location.reload()` ne suffit pas (Vite ré-émet l'import horodaté). Recette : lire l'URL réellement chargée puis l'importer — `const url = performance.getEntriesByType('resource').map(e => e.name).filter(n => n.includes('/src/lib/copilot.svelte.ts?t=')).pop(); await import(url)`. Symptôme diagnostique : `a.copilot === b.copilot` faux entre deux specifiers
