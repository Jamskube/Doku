## Situation
Gotchas — portée `pdf`. Entrée d'origine datée du 2026-07-24.

## Rule
Index incrémental par diff : un fichier volontairement SANS sortie a quand même besoin d'une entrée MARQUEUR.

## Evidence
Dans l'index d'embeddings du dossier (18.3), un PDF scanné (aucune couche texte) ou une note vide ne produit aucun chunk → tentation de le sauter sans l'enregistrer. Erreur : `diffFiles` compare l'ensemble scanné aux entrées persistées ; un fichier absent des entrées est vu comme **`added` à CHAQUE refresh** → retravaillé en boucle (ré-extraction pdf.js coûteuse), et la sortie rapide « rien changé → ready » ne se déclenche JAMAIS tant qu'un tel fichier existe. Correctif : enregistrer une entrée marqueur `{path, name, hash, chunks: []}` (0 ligne, traverse rebuild/persist/loadPersisted proprement) → le diff le voit **inchangé** ensuite. Signal de changement d'un binaire coûteux à lire (PDF) = `stat` (`size:mtime`), pas un hash d'octets (qui lirait tout le fichier) — l'extraction n'a lieu que pour les ajoutés/modifiés, dans la boucle à progression.
